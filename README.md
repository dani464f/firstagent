# Invoice Follow-Up Agent (CrewAI MVP)

Simple local MVP for a small service business to monitor open invoices and send escalating follow-ups.

## Assumptions
- Python 3.11+ is available.
- CSV files are the source of truth (no external DB).
- Console output is the default sender (safe for local testing).
- Escalation selection is deterministic and rules-based.
- LLM usage is limited to wording/tone generation only; pass `--no-llm` to run without LLM.
- A local lightweight CrewAI-compatible shim is included for offline execution in constrained environments.

## Setup
1. Create virtual environment and install dependencies:
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

   > Note: this repo includes a lightweight local `crewai.py` shim so the MVP runs offline.

2. Seed sample data:
   ```bash
   python -m app.seed_data
   ```

3. Run daily job with fixed date simulation:
   ```bash
   python -m app.run --today 2026-02-26 --no-llm
   ```

4. Run with CrewAI LLM message generation (optional):
   ```bash
   # configure provider env vars expected by CrewAI in your environment
   python -m app.run --today 2026-02-26
   ```

## Deterministic Business Rules
- **Pre-due** (`pre_due`) when due date is within `pre_due_window_days` (default 3) and client is consistently late:
  - `late_rate >= 0.6` OR `typical_payment_days > 10`
- **Overdue 3** (`overdue_3`) when `3 <= days_overdue < 14`
- **Overdue 14** (`overdue_14`) when `14 <= days_overdue < 30`
- **Overdue 30** (`overdue_30`) when `days_overdue >= 30`

## Anti-Spam Safeguards
- No follow-up for paid invoices.
- No duplicate follow-up type per invoice (checked against `followups_log.csv`).
- Cooldown: skip if `last_followup_date` is within last `cooldown_days` (default 3).
- Every decision logged in summary; every sent message logged with hash ID.

## CrewAI Design
- **Invoice Monitor Agent**: confirms immutable context for a candidate.
- **Message Composer Agent**: drafts subject/body using tone rules.
- **Compliance QA Agent**: validates required fields and professional language.
- **Dispatcher Agent (rules in code)**: prints to console and writes log row.

## How to swap console sender with real email (optional)
1. Create adapter module `app/senders/` with a shared interface:
   - `send(to_email: str, subject: str, body: str) -> None`
2. Replace `send_console_email(...)` call in `app/run.py` with selected adapter from config.
3. Example adapters:
   - **Gmail SMTP**: use app password + `smtplib`.
   - **SendGrid API**: use `sendgrid` package and API key.
4. Keep the dispatcher log write unchanged so dedupe/cooldown rules still work.
